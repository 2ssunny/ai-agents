# Human Review Checklist — AI Agent Output

AI 에이전트의 산출물을 검토할 때 사용하는 체크리스트입니다.
커밋하거나 배포하기 전에 반드시 확인하십시오.

---

## A. 지침(Instruction) 관리 체크리스트
지침 자체를 추가·수정했을 때 사용합니다.

- [ ] **충돌 검사**: `global_rule.md`의 내용과 각 `templates/` 또는 `skills/` 내용이
  서로 모순되지 않는가?
- [ ] **중복 검사**: 같은 규칙이 두 개 이상의 파일에 중복 기술되어 있지 않은가?
  중복이 있으면 한 곳에만 두고 나머지는 참조로 교체.
- [ ] **업데이트 주기**: 사용 중인 라이브러리·프레임워크의 메이저 버전업이
  지침에 반영되어 있는가?
- [ ] **환경 적합성**: 지침이 실제 개발 환경(Windows / conda / Docker / nginx 등)과
  호환되는가?

---

## B. 코드 리뷰 체크리스트

### 🔴 Critical (반드시 확인)
- [ ] **보안**: API 키, 토큰, 비밀번호, 절대 경로가 소스코드에 하드코딩되어 있지 않은가?
- [ ] **민감 파일 안전**: `.env`, `config.json`, `credentials.json`이 `.gitignore`에
  포함되어 있는가?
- [ ] **환각(Hallucination) 검증**: 존재하지 않는 라이브러리 메서드, 임의로 창작된
  수식(특히 퀀트 지표, 역학 공식 등)이 포함되어 있지 않은가?
  → 외부에서 독립적으로 공식 문서 또는 원전을 통해 수식을 교차 검증할 것.
- [ ] **실행 가능성**: 코드가 즉시 실행 가능한 완성된 형태인가?
  `// TODO`, `pass`, `...` 등 미완성 스텁이 남아 있지 않은가?

### 🟡 Important (강하게 권장)
- [ ] **오버엔지니어링 방지**: 간단한 스크립트에 불필요한 디자인 패턴
  (Factory, Singleton 등)이 과도하게 적용되어 있지 않은가?
- [ ] **에러 처리 완결성**: 외부 API 호출, 파일 I/O, subprocess 실행에
  예외 처리(`try/except`, `timeout`)가 빠짐없이 적용되어 있는가?
- [ ] **테스트 가능성**: 핵심 비즈니스 로직이 순수 함수(Pure Function)로 분리되어
  있어 독립적으로 테스트할 수 있는가?

### 🟢 Good Practice (권장)
- [ ] **코드 스타일 준수**: `code_style.md` 기준에 맞는 네이밍, 타입 힌트, 주석인가?
- [ ] **불필요한 의존성**: 단순 기능을 위해 무거운 라이브러리를 추가하지는 않았는가?
- [ ] **Git 커밋 품질**: 커밋 메시지가 Angular Convention을 따르고 있는가?
  하나의 커밋에 너무 많은 변경사항이 묶여 있지 않은가?

## C. 배포 전 최종 체크리스트

- [ ] Docker 컨테이너가 정상적으로 빌드되고 기동되는가?
- [ ] nginx 또는 리버스 프록시 설정이 올바른가? (`nginx -t` 통과)
- [ ] 필요한 환경변수가 모두 `.env` 또는 Docker secrets로 주입되어 있는가?
- [ ] 데이터 영속성(Docker Volume, 외부 DB 등)이 재시작 후에도 유지되는가?
- [ ] MFA, 인증 등 보안 계층이 정상적으로 작동하는가?
